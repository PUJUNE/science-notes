Field 13 · 도구 · AI 도구의 작동 원리

더 똑똑한 모델이 아니라 쓰는 방식이 다른 도구

로컬에서 실행되는 AI 코딩 도구가 웹 챗봇과 무엇이 다른지는 모델 성능이 아니라 실행 위치와 기억 구조에서 갈림. 신경망 파라미터가 무엇인지, 사전학습이 끝났다는 말이 무슨 뜻인지, 세션이 왜 기억을 잇지 못하는지를 순서대로 정리했음.

가중치 = 학습 후 고정  ·  세션 = 매번 초기화  ·  설정 파일 = 매 세션 다시 읽히는 기록

01실행 위치

브라우저 안이 아니라 파일 시스템 위에서 동작함

웹 챗봇은 브라우저 세션 안에서 대화하고 파일을 올리면 읽어서 답을 돌려주는 구조임. 로컬 실행 도구는 사용자의 컴퓨터에서 직접 돌아가면서 폴더와 파일을 읽고 쓰며, 필요하면 코드를 작성해 실행까지 수행함. 모델은 같은 수준을 쓰지만 접근 가능한 대상이 달라짐.

기존 브라우저 챗봇
  • 대화 상대로서의 AI
  • 파일을 올리면 읽고 답을 돌려줌
  • 웹 세션 안에서만 동작
  • 업로드한 분량 전체가 토큰으로 소모됨
로컬 파일 시스템 접근
  • 로컬 폴더·파일에 직접 접근
  • 파일을 만들고 수정까지 수행
  • 코드를 작성해 실행함
  • 필요한 부분만 코드로 발췌해 읽음
전제 지침이 필요함
  • 실행 범위가 넓어진 만큼 규칙이 필요함
  • 업무 지침에 해당하는 것이 설정 파일임
  • 지침이 없으면 매 세션 같은 설명을 반복해야 함

모델 수준은 같고 작동 방식이 다름. 지능이 아니라 편의성과 경제성에서 차이가 발생함.

02파라미터 = 가중치

학습은 숫자를 조금씩 바꾸는 과정임

신경망 그림에서 원 하나하나를 잇는 선에는 숫자가 저장되어 있고, 이 숫자를 파라미터 또는 가중치라고 부름. 학습이란 데이터를 반복 투입하며 이 숫자들을 조금씩 조정해 출력이 정답에 가까워지도록 만드는 최적화 과정임. 조정이 끝나면 학습이 종료되고 숫자는 고정됨.

출력 = f( W · 입력 + b )   — W가 가중치 행렬, b가 편향
W ← W − η · ∂L/∂W   — 경사하강법으로 손실 L을 줄이는 방향으로 갱신함
  • W가중치 행렬. 학습 대상인 숫자들
  • b편향 항
  • η학습률. 한 번에 얼마나 움직일지 정하는 값
  • L손실 함수. 정답과의 차이를 수치화한 값
  • ∂L/∂W손실을 가중치로 미분한 기울기. 어느 방향으로 줄여야 하는지 알려줌

학습률이 너무 작으면 최소점에 도달하기 전에 반복이 끝나고, 너무 크면 최소점을 지나쳐 진동하거나 발산함. 실제 모델 학습에서 학습률 조정에 시간을 쓰는 이유가 여기서 드러남.

03Pre-trained

출시 시점에 학습은 이미 끝나 있음

모델 이름에 붙는 버전 숫자는 학습 상태가 고정되었다는 표시임. GPT의 P가 Pre-trained의 P이고, 다른 모델도 같은 구조를 따름. 대화하면서 사용자의 정보를 기억하는 것처럼 보이는 동작은 가중치가 갱신되는 것이 아니라, 시스템이 따로 기록해 둔 내용을 매번 다시 읽어 참조하는 것임.

추가 학습이 안 되는 이유

학습이 끝난 모델에 새 데이터를 넣어 추가로 학습시키면 기존 가중치가 뒤틀려 이전에 잘하던 작업의 성능이 무너짐. 이를 파국적 망각(catastrophic forgetting)이라 부르며, 현재까지 일반적인 해법이 없는 제약임. 그래서 사용자 정보는 가중치로 기억시킬 수 없고 설정 파일로 별도 관리해 매 세션 다시 읽히는 방식을 씀.

구조적 귀결 — 가중치가 고정되어 있으므로 개인화는 학습이 아니라 참조로 구현됨. 설정 파일과 메모리 폴더는 이 참조 대상을 체계적으로 관리하기 위한 장치임.

04세션

새 대화창은 이전 대화창의 내용을 갖고 있지 않음

새 대화창을 열면 이전 세션에서 오간 내용은 전달되지 않음. 이어서 작업하려면 정보를 파일로 남겨 두고 다음 세션이 그 파일을 읽게 만들어야 함. 설정 파일과 메모리 폴더가 필요한 이유가 여기 있음.

계층지속 범위갱신 주체
가중치모델 버전 전체학습 시점에 고정. 사용자가 바꿀 수 없음
세션 맥락대화창 하나대화 진행에 따라 누적. 창을 닫으면 소멸
설정 파일영구사용자가 직접 편집. 매 세션 시작 시 로드
메모리 파일영구대화 중 기록 요청으로 생성. 인덱스를 통해 선택 참조

05토큰

토큰은 글자를 세는 단위이자 곧 비용임

모델은 문자열을 토큰 단위로 쪼개 처리하고, 처리한 토큰 수가 비용과 처리 한도를 결정함. 한글은 영어보다 토큰당 담기는 글자 수가 적어 같은 분량이라도 토큰 소모가 큼. 긴 문서를 다룰 때 웹 업로드와 로컬 발췌 방식의 비용 차이가 여기서 벌어짐.

모델 3종의 위치

01 상위 모델

복잡한 추론과 분석에 사용함. 토큰 단가가 가장 높음.

02 균형형 모델

일반 업무 자동화와 보고서 작성의 주력. 비용 대비 성능이 가장 효율적임.

03 경량 모델

단순 분류·요약·반복 호출에 적합함. 단가가 가장 낮음.

웹 업로드 방식은 문서 전체를 업로드 토큰과 인식 토큰으로 소모하므로 필요 없는 페이지까지 전부 읽어 들임. 로컬 실행 방식은 파일이 이미 사용자의 컴퓨터에 있으므로 검색 코드를 작성해 필요한 구간만 발췌해 읽음. 600쪽 규모의 문서 비교·검색 작업에서 차이가 크게 벌어짐.

06설정 3층

상시 규칙·개별 기록·반복 절차의 세 층

설정은 적용 범위와 갱신 주기가 다른 세 층으로 나뉨. 모든 세션에 항상 적용되는 규칙, 특정 사건을 적어 둔 기록, 특정 업무를 표준 절차대로 처리하는 매뉴얼이 각각 다른 파일에 들어감.

  • 상시 규칙모든 세션에 자동 로드되는 기본 지시문. 문체·금지어·응답 원칙 등 공통 규칙의 저장소임. 매번 같은 지시를 반복할 필요를 없앰.
  • 개별 기록메모리 폴더의 파일들. 언제 누구와 무슨 일이 있었는지를 적어 둔 기록이며, 인덱스를 먼저 읽게 해 두면 필요한 것만 골라 참조함.
  • 반복 절차스킬과 서브에이전트. 특정 업무를 표준 양식대로 자동 처리하기 위한 절차 매뉴얼이고, 반복 빈도가 높을수록 이 층에 올려 두는 편이 유리함.

완전 자동 기억이 아니라 체계화된 참조라고 이해하는 편이 정확함. 기록해 달라고 요청하면 파일로 저장되지만, 새 세션이 그 내용을 자동으로 아는 것은 아니고 인덱스를 먼저 읽도록 규칙에 명시해 둔 덕분에 참조가 일어남.

설정 파일은 컴퓨터 단위로 존재하므로 같은 계정이어도 노트북과 데스크톱이 자동 동기화되지 않음. 팀 공용 규칙이 필요하면 대표 파일을 공유 폴더에 두고 각자 설치하는 방식을 씀. 같은 파일을 쓰면 누가 실행하든 동일한 양식의 결과물이 나옴.

07한계

검수 가능한 범위 안에서만 자동화 도구임

모르는 분야는 결과가 틀렸는지 판단할 수 없음. 새 업무를 학습하는 것을 대체하는 도구가 아니라 이미 판단할 수 있는 업무를 가속하는 도구로 두는 편이 정확함.

항목내용대응
검수 범위모르는 분야의 결과는 옳고 그름을 판별할 수 없음판단 가능한 업무에 한정해 적용함
소스 품질녹취록·OCR 결과가 틀리면 산출물도 틀림원자료를 먼저 검토한 뒤 투입함
파일 안전성파일을 직접 다루므로 원본 훼손 가능성이 있음실행 전 권한 확인이 뜨며, 원본은 복사본을 작업 폴더에 두고 처리함
토큰 한도긴 작업은 한도에 걸릴 수 있음작업을 분할하고 중간 결과를 파일로 남김
동기화설정이 컴퓨터 단위로 존재함공유 폴더에 대표 파일을 두고 각 컴퓨터에 설치함

적용 시작점 — 전체를 한 번에 이해할 필요 없이 현재 업무에서 반복되는 문서 작업 한 건을 잡고 시작하는 편이 진입 비용이 낮음. 반복 빈도가 높은 작업일수록 절차 매뉴얼로 올려 두는 이득이 커지고, 한 번만 하는 작업은 그때그때 지시하는 편이 나음.
